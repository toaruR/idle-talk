## 1. 背景・問題・目的・非目標

### 1.1 問題
常駐する日本語雑談アプリを、既存 GPU 資源（RTX 3060 x2、GPU1 は他アプリ使用中）を壊さずに作る。既存の音声対話は割り込み・停止不能・遅延で雑談の楽しさを損なう。

### 1.2 目的（測定可能）
|ID|目的|目標値（試行数）|
|---|---|---|
|G1|発話終了から意味のある最初の音声まで|p50 ≤ 1.2s, p95 ≤ 2.0s（50 ターン）|
|G2|利用者の発話開始から AI 音声の低下（ダッキング）または停止の開始まで（VAD 経路）|p95 ≤ 250ms（50 回）|
|G3|停止（キャンセル確定）後に旧世代の音声が鳴る|0件（100 回の注入試験）|
|G4|話の途中を終話と誤判定|50 試行で 2 件以下|
|G5|8時間連続運転|メモリ増加の回帰傾き ≤ 1MiB/h、音声が止まらない|

### 1.3 非目標
本書末尾の「範囲外」行を唯一の定義とする。

### 1.4 制約・前提
- 利用者は同時に1人。家族などが入れ替わって使う場合は声で見分けて名前で呼ぶ（§6.4）。ヘッドホン・スピーカーのどちらでも使う（スピーカーの回り込みはブラウザの AEC と §5.1 の自声除外で抑える）。ブラウザは localhost のみ接続。
- 資源上限（超えたら構成見直し）：LLM は GPU0 で 9GiB 以内、ASR 追加 3GiB 以内、アプリ全体で追加 RAM 8GiB 以内。GPU1 は既存アプリ優先。
- 常駐プロセスは3つ：Python 本体（Director）、llama-server、AivisSpeech Engine。llama-server は Director が子プロセスとして起動・監督し、異常終了を `LLM_RETRY` で再起動する（起動引数は設定ファイルの `[llm]`）。

## 2. アーキテクチャ

### 2.1 コンポーネント
ブラウザ（マイク/AudioWorklet・再生キュー・UI）⇄ WebSocket ⇄ Director（状態機械）。Director は VAD（CPU）、ASR（GPU0）、SQLite、llama-server（GPU0）、AivisSpeech（CPU）を呼ぶ。Topic Worker は M4 以降に SQLite へ書く。

### 2.2 技術選定
LLM は Qwen3.5 Q4_K_M（既定 4B、ctx 4k、思考無効はテンプレート設定）、ASR は ReazonSpeech（sherpa-onnx、int8）を CPU、TTS は AivisSpeech を CPU に置く（faster-whisper small を GPU0 に戻すことも設定でできる）。各配置の切替条件は §8.1/§9。

## 3. インターフェース契約

### 3.1 WebSocket プロトコル（ブラウザ <-> Director）
接続は `ws://127.0.0.1:<port>/ws`。バインドは 127.0.0.1 のみ。Origin が localhost 以外の接続は拒否する。同時接続は1本。2本目の接続は旧接続を閉じて置き換える（close code 4001）。

|方向|種別|ペイロード|備考|
|---|---|---|---|
|B→D|binary|16kHz mono s16le PCM、20〜40ms/フレーム|先頭に 4byte の連番 (u32 LE)。最上位ビット (`DRAMA_FLAG`) が立っていれば共有したタブの音（§6.5）|
|B→D|`hello`|§12.1|接続直後。version 不一致なら close 4002|
|B→D|`playback`|§12.1|実再生位置の通知|
| 共通 | `ping`/`pong` | §12.1 | `PING_INTERVAL` ごと。欠落 2 回で切断扱い |
|B→D|`ui`|§12.1|設定変更（`drama`: ドラマモードの on/off、§6.5。`screen`: 画面モードの on/off、§6.7。`camera`: カメラモードの on/off、§6.9。`transcribe`: 文字起こしモードの on/off、§6.10）|
|D→B|binary|16byte ヘッダ + PCM（§12.1）|先読みは1チャンクまで|
|D→B|`duck`|§12.1|音量を下げる|
|D→B|`cancel`|§12.1|new_epoch 未満のキューを全破棄|
|D→B|`resume`|§12.1|ダッキング解除し続きから再生|
|D→B|`state`|§12.1|UI 表示用|
|D→B|`search`|`{"t":"search","query":str,"active":bool}`|Web 検索の開始/終了（§6.3。UI 表示用、§12.1 のスキーマ外）|
|D→B|`links`|`{"t":"links","items":[{"title":str,"url":str}]}`|調べたページの URL を画面の URL 欄に出す（§6.3。§12.1 のスキーマ外）|
|D→B|`transcript`|`{"t":"transcript","speaker":str,"text":str,"ts":int}`|文字起こしの 1 発話（§6.10。§12.1 のスキーマ外）|
|D→B|`snap`|`{"t":"snap","id":u32}`|今の画面を 1 枚求める（§6.5）|
|B→D|`snap`|`{"t":"snap","id":u32,"jpeg"?:base64,"thumb"?:base64,"reason"?:str}`|求められた画面（640×360 に収めた JPEG、base64 で最大 1MiB）。`thumb` は 32×18 の明るさ 1 バイトずつの縮小画像（§6.7 の変化の判定用）。映像が無い・描けなければ `jpeg` を省き、理由（200 字まで）を `reason` に入れる（Director がログに残す）|
|共通|`error`|§12.1||


### 3.2 epoch 契約
- epoch は Director が単調増加で管理する u32。キャンセル確定時のみ +1 する。
- すべての生成物（LLM ストリーム、TTS 結果、音声チャンク）は生成開始時の epoch を持つ。epoch が現在値と異なる結果は到着時に破棄する（受信側の責務）。
- ブラウザは `cancel.new_epoch` 受信時、キュー内と再生中の旧 epoch チャンクを即時に破棄し、以後は旧 epoch のチャンクを受理しない。

### 3.3 外部サービス契約
|相手|呼び出し|タイムアウト|失敗時|
|---|---|---|---|
| llama-server | `/v1/chat/completions` stream | `HTTP_TIMEOUT`（§8.1） | 定型句で応答しログ。再試行は `LLM_RETRY` |
| AivisSpeech | `/synthesis`（§12.1。中止後の残計算の検証は T-E8） | `HTTP_TIMEOUT` | 該当文を飛ばし、テキストのみ UI に表示 |
|ASR ワーカー|内部キュー|`HTTP_TIMEOUT`|該当発話を破棄しログ。次の発話へ|
|Web 検索（§6.3）|DuckDuckGo lite → Bing の HTML、上位 1 件の本文は r.jina.ai。`[search].realtime` なら Yahoo! リアルタイム検索で X の投稿も|1 回 8s|次のエンジンへ。全滅なら「調べられなかった」と答える。本文が読めなければ抜粋だけで答える。X の投稿が取れなければ Web の結果だけで答える|

制約：AivisSpeech は `/synthesis` を使う（`/cancellable_synthesis` は AivisSpeech Engine 1.2.0 で未実装）。`/synthesis` は切断後も計算が続くため、合成は 1 文ずつ要求して残計算を 1 文ぶん（`HTTP_TIMEOUT.tts_sentence` 以内）に抑え、中止した文の結果は epoch 不一致で破棄する。残計算の収束は T-E8 で検証する。初回合成は GPU 初期化で遅いため、Director 起動時に 1 回空合成してから待ち受ける（失敗はログのみで起動は続行）。

### 3.4 SQLite スキーマ（概要）
|テーブル|主な列|
|---|---|
|`events`|id INTEGER PK, ts INTEGER, epoch INTEGER, kind TEXT, payload_json TEXT|
|`turns`|id INTEGER PK, ts INTEGER, role TEXT, text TEXT, completed INTEGER(0/1), stop_position_ms INTEGER NULL, utterance_id INTEGER|
|`topic_cards`|id INTEGER PK, hook TEXT NOT NULL, facts TEXT(JSON), source_url TEXT, published_at INTEGER(epoch ms), expires_at INTEGER, angle TEXT, used_at INTEGER NULL, user_reaction TEXT NULL|
|`memories`|id INTEGER PK, content TEXT, evidence_utterance_id INTEGER, updated_at INTEGER, deletable INTEGER, persona TEXT NULL（§6.6。NULL は全ペルソナ共通）|
|`speakers`|id INTEGER PK, name TEXT NULL, embedding BLOB（float32 の単位ベクトル）, n INTEGER（平均に使った発話数）, updated_at INTEGER（§6.4）, alias TEXT NULL（文字起こしの仮名、§6.10）|

WAL モード、書き込みは専用スレッドのキュー経由。スキーマ版は `PRAGMA user_version`。

## 4. 状態機械（Director）

### 4.1 状態
`待機 → ユーザー発話中 → 終話確認中 → 返答準備中 → AI再生中 → 割り込み確認中 → 休止`

### 4.2 遷移表
|現状態|イベント|ガード|次状態|アクション|
|---|---|---|---|---|
|待機|VAD 発話開始|ミュートでない|ユーザー発話中|ASR へ区間送出開始、記憶抽出中断。自発発話は `duck` して取消を認識結果まで保留（語があれば取消、無ければ `resume`）|
|ユーザー発話中|VAD 発話終了|区間 ≥ `MIN_SEG`|終話確認中|終話判定タイマ開始|
|ユーザー発話中|VAD 発話終了|区間 < `MIN_SEG`|待機|区間破棄（雑音扱い）、イベント記録|
|終話確認中|無音が `T_silence` 継続|終話判定が「終話」|返答準備中|ASR 確定、LLM 呼び出し|
|終話確認中|VAD 発話再開|-|ユーザー発話中|タイマ取消（言いよどみ）|
|返答準備中|最初の合成可能な節|epoch 一致|AI再生中|TTS→再生キュー|
|返答準備中|VAD 発話開始|-|ユーザー発話中|生成を取消、epoch+1|
|AI再生中|VAD 発話開始|-|割り込み確認中|`duck`（強い発話・停止語なら即 `cancel`）|
|AI再生中|全チャンク再生完了|-|待機|履歴確定|
| 割り込み確認中 | 相槌と判定 | `T_confirm` 内 | AI再生中 | `resume` |
|割り込み確認中|割り込みと判定 / 判断不能 / `T_confirm` 超過の相槌|語が認識された|ユーザー発話中|`cancel`、epoch+1、旧生成物破棄、TTS 計算停止|
|割り込み確認中|VAD 発話終了|区間 < `MIN_SEG`|AI再生中|`resume`（物音）|
|ユーザー発話中 / 終話確認中 / 割り込み確認中|認識結果を破棄（ASR 失敗・幻聴・語なし・自声）|最新の区間で発話が終わっている|待機（割り込み確認中なら AI再生中）|区間破棄、割り込み確認中なら `resume`|
|任意|ミュート/長時間無操作/連続失敗|-|休止|背景処理停止、LLM はロード維持（省電力モード時のみ解放）|
|休止|解除操作|-|待機|解放していた場合はウォームアップ|

### 4.3 不変条件
1. 音を止める処理は LLM・ASR の完了を待たない。
2. AI 再生中もマイクと VAD を止めない。
3. 通常応答・自発発話・相槌クリップは同一の再生・キャンセル経路を通る。
4. 履歴に確定するのは再生完了チャンクのみ（送信完了は再生完了ではない）。
5. 沈黙は自発発話の同意ではない。

### 4.4 並行性の規則
- 状態遷移は Director 単一コルーチンで直列化する（イベントキュー）。外部コールバックは遷移を直接変更せずイベントをキューに積む。
- キャンセルと完了が競合した場合、epoch 比較で後勝ちを決める（旧 epoch の完了通知は無視）。

## 5. 割り込み・再生済み履歴

### 5.1 判定
- 相槌：短い発話で「うん」「へえ」等。割り込み：`STOP_WORDS`（§8.1）または `STRONG_UTT`（§8.1）を満たす発話。
- 「うん？」は疑問、「いや」は訂正になりうるため、短い発話を一律に相槌とみなさない。
- 認識結果が出るまでは `duck` のまま待ち、時間切れでは止めない。語が出なかった（物音・ASR 失敗・幻聴）なら再生を続け、語が出て相槌でなければ停止する。
- 文脈の無い短い認識結果：`[asr].short_chars`（2）字以下の結果は、AI の声の最中に始まった発話か、AI の声を最後に再生してから `[asr].short_reply_s`（20 秒）以内のときだけ使い、それ以外は語なしとして捨てる（events に `short_discarded` を 1 行）。ReazonSpeech は食器・咳を「はい」「誰」「ハハ」と聞き違え、Silero VAD の声らしさも ASR の確信度も本物の短い返事と重なって見分けられなかった（2026-10-15）。何もないところに 2 字だけ話しかけても応答しない。
- 自声除外：AI 再生中（自発発話を含む）に始まった発話の認識結果が、直近の AI 発話本文に句読点・空白を除いた部分文字列として含まれれば、スピーカーからの回り込みとして捨てる（応答も停止もしない。events に `echo_suppressed` を 1 行）。言い換えや部分的な誤認識は検出できない。
- VAD は RMS が閾値以上のフレームが `[vad].onset_ms` 続いたら発話開始とし、一瞬の物音を無視する。開始判定までの音は区間の頭に含める。閾値と onset は設定ファイルの `[vad]`。さらに前の 300ms（`ingress.PRE_ROLL_MS`。閾値に届かない小声の出だし）も ASR に渡す（区間の長さ・`MIN_SEG` には数えない）。
- 出だしの区間の継ぎ足し：`MIN_SEG` 未満・幻聴・語なし・文脈の無い短い結果で捨てた区間は、その終わりから 1 秒（`ingress.JOIN_GAP_MS`）以内に次の区間が始まれば、その頭に足して認識し直す（発話が VAD で割れ、出だしの 1 字だけの区間が捨てられて最初の何語かが欠けた、実機 2026-10-19）。自声・ドラマ・PC の回り込みで捨てた区間は足さない。次の区間を認識に出した後に捨てると決まった区間は足せない。
- 閾値の自動校正（`[vad].adaptive`、既定オン）：非再生中のフレームから周囲の雑音を推定し（静かな方へ速く、うるさい方へ毎秒 0.5dB でゆっくり追う）、閾値を「雑音 × `ratio`」（下限 `min_threshold`）とする。AI 再生中は回り込みの平均を別に測り、閾値を「回り込み × `ratio`」以上に上げる。ドラマモードでタブの音が鳴っている間（ドラマ側の閾値を超えてから 0.3 秒 `BLEED_HOLD_S`）も、その回り込みを AI とは別に測って同様に上げる（タブの音はブラウザの AEC で消えないため、スピーカーだと笑い声・BGM を「はい」「ハハ」等と認識した）。ブラウザの AGC は推定を乱すので切る（`autoGainControl: false`）。
- 既定はダッキング優先（強い発話・`STOP_WORDS` は即停止）。見直しは M1 で誤停止率と相槌頻度を見て行う。停止の確認窓は `T_confirm`（§8.1）。

### 5.2 履歴確定ルール
- チャンクは `epoch/utterance_id/chunk_id` で識別し、ブラウザの `playback` で実再生位置を得る。完了チャンクのみ履歴に確定し、途中停止は「中断された発話」として停止位置付きで記録する。
- 単語時刻が無い場合、再生秒数から聞こえた文章を推定しない。

## 6. 拡張設計

### 6.1 AI の相槌（M2〜）と自発発話（M3〜）
- 相槌：長めの発話中に無音が `SIL_BACKCHANNEL` 継続したとき、内容非依存の事前合成クリップを再生。1発話最大1回、`BC_COOLDOWN` を置く。誤発火は全記録。
- 自発発話：設定（オン/オフ、頻度、休止時間帯）は §8.1。雑談モードのみ。無反応なら連続せず待ち時間を延ばす。準備中に発話があれば取消す。

### 6.2 Pipecat への移行条件
スピーカー必須化、デバイス保守負荷の増大、別端末接続の要望のいずれか。先に自前 WebSocket の `getUserMedia({echoCancellation:true})` を実測し、合格条件は自分の声に応答が連鎖しないこと。

### 6.3 Web 検索
- 通常応答のときだけ、system に「調べないと答えられない質問・『もっと詳しく』には 1 行で『検索: 検索語』とだけ出力」という指示（今日の日付つき）を足す。自発発話では検索しない。
- 「検索:」「リンク:」は返答の先頭とは限らない（実機の 4B は前置きの後や末尾に書いた）。節ごとに探し、指示より前の文だけ読み上げ、指示以降は読まずに LLM の受信を閉じる。検索語は指示の後ろ（その節の残り）。
- 検索を始めたら「ちょっと調べてみるね。」を通常の再生経路で流し、`search` (active=true) を送る。5 秒を超えたら「もう少し待ってね。」を 1 回だけ流す。
- 結果（上位 5 件の見出しと抜粋 800 字 + 上位 1 件の本文抜粋 800 字）を最後の利用者発話に添え、履歴を直近 4 ターンに絞って答え直させる（ctx 4k に収める）。結果に無いことは推測させない。
- 直近の検索結果、または自発発話で使った話題カードの記事（http(s) の URL のみ）を保持し、ある間だけ「ページや URL を求められたら 1 行で『リンク:』とだけ出力」という指示も足す。「リンク:」なら URL は読み上げず「画面に表示するね。」と言い、`links` で画面の URL 欄に出す。LLM が書いた URL は使わない。
- 話題カードで話すときは、聞かれる前に記事の URL を `links` で出す。
- 話題カードの選び方（2026-10-28）：未使用・未期限切れのカードを、見出しと概要のポジティブ度（`topics.card_tone`：`POSITIVE_WORDS` の語の数 − `NEGATIVE_WORDS`（事故・死亡・災害等）の語の数 × 2）の高い順、同じなら新しい順に並べる。候補が 2 枚以上なら、その上位 `topics.PICK_MAX`（8）件の見出しを会話用 LLM に渡し、一番明るいものを番号で答えさせて使う（`topics.pick_messages`。8 件で約 300 トークン）。答えに範囲内の番号が無い・呼び出しが失敗したら語の点数の 1 位を使う。選んでいる最中に利用者が話し始めたら（自発発話の取消）、LLM を止めてカードは使用済みにしない。暗い記事は捨てず、他のカードが尽きたときに使う。
- X の投稿（`[search].realtime`）：検索のたびに Yahoo! リアルタイム検索で同じ語の新しい投稿 3 件を取り、Web の結果とは別枠（400 字）で添える。投稿は個人の発言なので「〜という声がある」と伝えさせる。
- X のトレンド（`[topics].x_trends`）：Topic Worker が定期取得のたびにリアルタイム検索のトレンド上位 3 件を取り、各語の新しい投稿を概要にして話題カードにする（有効 6 時間、自発発話では「X で話題」として話す）。
- 話題カードの補充：自発発話でカードを使い、未使用カードが尽きたら（最後の 1 枚を使った時点で）Topic Worker に補充を要求する。Worker は定期取得を待たずにフィードを取り直し、新着が無く `[search].on` なら Bing ニュース（新しい順）をジャンル順に 1 つ検索して記事をカードにする（概要の無いもの・トップや一覧ページは除く。重複は URL で除く）。要求は 5 分（`REFILL_MIN_S`）に 1 回まで、休止中は無視。
- 画面の URL 欄は URL 自体をリンクにして（タイトルは添え書き、クリックで別タブ）先頭に積み（新しいものが上）、100 行を超えたら古い順に消す。同じ URL は付け直して先頭へ。
- 検索中の割り込みで epoch が変わっていたら 2 回目の LLM は呼ばない（不変条件 1。検索の HTTP は打ち切らず結果を捨てる）。
- 見ているページ（`[search].read_window`、既定オン、Windows のみ。`browser_page`）：利用者の発話が「この（その・今見てる）ページ／記事／サイト」等と意見・感想・要約の語を含めば（`wants_page`。LLM の指示ではなく文字で判定）、「ちょっと読んでみるね。」と言い、前面から Z 順で最初のブラウザ（クラス `Chrome_WidgetWin_1` でタイトル末尾が「- Google Chrome」「- Microsoft Edge」。VS Code・Obsidian も同じクラス）のアドレスバーを UI Automation（PowerShell の `System.Windows.Automation`。値は `https://` が省かれる）で読み、r.jina.ai で本文を取る（15 秒。記事ページで約 7 秒かかった）。メニュー等の 20 字未満の行を除き、ページのタイトルが出る位置から 1500 字を最後の利用者発話に添え、履歴を直近 4 ターンに絞って答えさせる。idle-talk 自身・`[screen].exclude` の語を含むウィンドウは読まない。読み取った URL はすぐ `links` で画面の URL 欄に出す（「URL を教えて」でも出る）。
- ページの要約（2026-10-21）：見ているページを頼む発話が「要約」「まとめ」を含めば（`wants_summary`）、本文は読まず LLM も呼ばずに、アドレスバーの URL から `https://chatgpt.com/?q=<URL> を日本語、小学生にも分かるように箇条書きで要約して`（URL エンコード）を既定のブラウザの新しいタブで開き（`webbrowser.open`）、「ChatGPT で要約を開いたよ。」と言う。URL が取れなければ「見ているページが分からなかった」と言う（画面では答えない）。
- URL が取れない・本文が読めなければ、LLM が画像を読めるとき（`/props` の vision）だけ前面のウィンドウを撮って（`wincap.WindowCapture`、§6.7 と同じ大きさ・色数）画像で答える。どちらも無ければ「見ているページが分からなかった」と言う。外部に出るのは読むページの URL だけ（画面は送らない）。

### 6.4 話者識別
- `[voice_id].on` のときだけ有効。区間が `MIN_VOICE_MS`（1500ms）以上の発話について、WeSpeaker ResNet34 の ONNX モデル（入力は Kaldi 互換 80 次元 fbank から時間平均を引いたもの）で声の特徴（話者埋め込み）を CPU で計算する。ASR と並行して別スレッドで計算し、応答遅延（G1）に足さない。CPU は TTS と共有するのでスレッド数は 2 に抑える。
- 照合は認識結果を採用した発話（語なし・幻聴・自声 §5.1 で捨てたものを除く）だけで行う。保存済みの声とのコサイン類似度の最大値が `[voice_id].threshold`（既定 0.6。AivisSpeech の 6 話者 x 3 文で同一話者の最小 0.71、別話者の最大 0.55 の間。似た声の 1 組は 0.82 で分離できなかった）以上ならその人とし、声の平均を更新する（過去分の重みは `MAX_WEIGHT`=20 で頭打ち）。短い発話は判定せず直前の相手を引き継ぐ。名前の無い登録済みの声への切り替えは 2 回続けて一致したときだけ行い、1 回目は直前の相手のままにする（利用者の声が 1 回だけ文字起こし・ドラマで溜まった名前なしの声に 0.67 で一致し、名前をまた尋ねた。実機 2026-10-19 / 10-26）。今回登録した声は既に `ENROLL_N` 回一致しているのですぐ切り替える。
- 知らない声は `ENROLL_N`（2）回続けて互いに一致したら名前なしで登録する（物音やテレビの 1 回で登録しない）。事前登録は不要。
- 名前の分からない登録済みの相手には、通常応答の返答の後に定型の質問「なんて呼べばいい？」を読む（4B は system の「名前を尋ねて」を無視しがちなので LLM には任せず、system には「名前は知らない。最後に質問しない」とだけ足す）。尋ねた扱いは最後まで再生されたときに確定し、割り込みで止まったら次の応答で改めて尋ねる（1 人あたり起動中 `ASK_MAX`=2 回まで。自発発話では尋ねない）。その人の次の発話への応答には「名乗っていればその名前で挨拶」を足し、再生完了後の背景処理（記憶抽出の前）で LLM に名前だけを抜き出させる。名乗らなければ次の応答で改めて尋ねる。
- 名前の分かった相手は system に「今話している相手は〇〇さん」と添える。
- 名前の無い声は、最後に一致してから `[voice_id].forget_days`（既定 3 日）で起動時に消す。一致が `FEW_N`（3）回以下の声（物音・テレビの一言）は `forget_few_days`（既定 1 日）で消す（0 なら消さない）。文字起こし・ドラマのテレビの声が溜まると、利用者の声がそれに一致して名前をまた尋ねた（2026-10-26）。よく聞く声は一致のたびに `updated_at` が新しくなるので残り、文字起こしの仮名も保たれる。
- 同じ名前を名乗った登録は声の平均をまとめて 1 件にする（マイクや部屋が変わって別人扱いされたときの戻し方）。
- 埋め込みの計算に失敗したら話者識別だけ諦め、認識結果は通常どおり使う。モデルが無ければ起動時に warn して識別なしで動く。
- 限界：声の似た人（家族など）は取り違えうる。同時に複数人が話す会話は扱わない。

### 6.5 ドラマモード
- 画面の「ドラマを一緒に見る」で `getDisplayMedia` によりタブ（画面）を共有し、その音声だけを別の AudioWorklet で 16kHz に落として同じ WS で送る（seq に `DRAMA_FLAG`）。映像トラックは即停止する（画面を見るとき（下記）は残す）。共有中は `ui.drama=true`。
- ドラマの音は専用の VAD で区間化し（`[drama].max_seg_s` で強制分割）、別の単一ワーカーで ASR にかける（利用者の認識を待たせない）。認識結果は直近 `window_s` 秒だけメモリに置く。FSM・相槌・E6 には入れない（台詞は利用者の発話ではない）。
- 一言：IDLE で、台詞が `gap_ms` 以上途切れ、前の一言から `interval_s` 以上経ち、新しい台詞が `min_chars` 字以上溜まったら、自発発話と同じ経路（pending・保留・取消・再生完了）で LLM に一言（25 字以内）を求める。全文を受け取ってから、「なし」なら黙る。生成中に台詞が再開していたら、かぶせずに次の切れ目を `DRAMA_HOLD_S`（8 秒）まで待って言い、来なければ黙る（1 行目だけを読む）。「聞こえない・分からない」系の一言も黙る。ドラマモードをオフにしたら作りかけ・再生中の一言も取消す。黙った場合も間隔は空ける。
- 総合的な感想：台詞が `finale_gap_s`（60 秒）聞こえず（見終わった・一時停止）、前の感想から `finale_min_chars` 字以上聞いていたら、それまでの感想を 2〜4 文で話す（一言と同じ経路。一言より優先）。`window_s` を過ぎた台詞は捨てるので、台詞が `digest_chars` 字溜まるたびに裏で LLM に 60 字以内のあらすじメモへ要約させて覚えておく（メモは計 `NOTES_MAX_CHARS`=1200 字まで、古い方から捨てる。要約は利用者の発話で取消し、台詞を残して再試行）。感想にはメモとまだ要約していない最後の台詞を渡し、話したらメモを捨てる。メモもメモリにだけ置く。
- 通常応答の system には直近の台詞（`ctx_chars` 字まで、古い方から捨てる）を添える。一言には会話履歴も前の一言も渡さず、前の一言以降の台詞（今の場面）だけを見せる（履歴や古い台詞を見せると 4B が同じ語を繰り返した）。
- 回り込み：マイクの認識結果の 6 割以上（4 字以上）が直近の台詞と連続一致したら、スピーカーから拾ったドラマの台詞として捨てる（events に `drama_echo_suppressed`）。マイクの発話がタブの音と重なっていたら（`sounding()` の間に発話中だった）、重なった台詞の区間が閉じて認識が出るまで（上限 `max_seg_s`×2+2 秒）マイクの認識結果を渡さずに待ち、2〜3 字でも台詞にそのまま含まれれば捨てる。Chrome の外のアプリ（動画ビュワー等）の音はブラウザの AEC で消えず、マイクの認識が先に出て「二年前」等が利用者の発話として通った（実機 2026-10-19）。待つ間は利用者への応答もその分遅れる。
- 回り込みの音量と声：重なった発話は文字より先に音量で見る（`drama.BleedMeter`）。タブの音が鳴っている間のマイクとタブの音量の差（dB、タブは直近 0.3 秒の最大）の中央値を回り込みの比とし、発話のうち「タブの音量 + 比 + 6dB」を超えるフレームが 3 割未満なら回り込みとして待たずに捨てる。1.5 秒以上の発話は、名前の分かった相手の声との類似度が `DRAMA_VOICE_MIN`（暫定 0.45）未満でも捨てる（events の `drama_echo_suppressed` に理由 `by`=level / text / voice）。重なった発話からは新しい声を登録しない（ドラマの人物が名前なしで 15 人たまった、2026-10-19）。文字の一致は、ドラマ側の区間が幻聴で捨てられたときや「三十畳」→「何十畳」の違いで漏れた。
- 聞くだけ：`[drama].mic`（既定 true）か画面の「ドラマ中もマイク」（`ui.drama_mic`）を切ると、ドラマモード中はマイクを聞かない（一言・感想は続ける）。ミュートは休止になって一言も止まるため別に設ける。
- ドラマモード中は名前を尋ねない（動画の声は名乗らない）。
- AI の声の混入：画面全体をシステム音声つきで共有すると、idle-talk のタブが鳴らす AI の声もドラマの音に入り、台詞として一言・感想に使われた（実機 2026-10-17）。ブラウザは共有の音声に `restrictOwnAudio`（Chrome 141+）を付けて自分のタブの音を除く。Director も、ドラマの認識結果の 6 割以上（3 字以上の一致の合計、4 字以上の結果のみ）が直近 2 回の AI 発話の本文と一致したら台詞に足さない（events に `drama_self_suppressed`。`drama.is_ai_voice`）。
- ドラマモード中は普段の自発発話と `IDLE_TIMEOUT` 休止を止める。共有停止で台詞を捨てて元に戻る。
- 画面：`[llm].mmproj` を指定し、llama-server が画像入力に対応しているとき（起動後の `/props` の `modalities.vision`。`/config.json` の `vision` でブラウザに伝える）だけ使う。ブラウザは映像トラックを残し、一言・感想の直前に `snap` で求められたら今の 1 コマを 640×360 に収めた JPEG（品質 0.7）で返す。Director は `SNAP_TIMEOUT_S`（2 秒）だけ待ち、届けば user の `content` を文章 + 画像にして「映っている様子も踏まえて」と足す。来なければ画像なしで言う。画像つきの呼び出しが失敗したら画像なしで 1 回だけ呼び直す。あらすじメモの要約と通常応答には使わない（G1 に足さない）。画像はメモリにだけ置き、使ったら捨てる（ログは大きさだけ。確認用に `[drama].keep_snaps` 枚だけ `data/snaps` に残せる、§7）。
- 限界：画面は一言・感想の時点の 1 コマだけで、場面の流れ（動き）は分からない。画面を使わないときは音だけで映像は分からない。BGM・効果音は幻聴フィルタと語なし判定に頼る。

### 6.6 ペルソナ
- 設定ファイル（`idle_talk.toml`）と同じフォルダの `personas.toml` に、id ごとの表で `name`（AI 自身の名前）・`label`（画面の表示名、省略時は `name`）・`prompt`（性格・口調・一人称）を書く。声は持たせず、画面の「声」（`ui.speaker`）で別に選ぶ。トップレベルの `default` が起動時のペルソナ（省略時は先頭）。ファイルが無ければ組み込みの 1 人（気さくな雑談相手）だけで動く。
- system プロンプトは「名前の節（「あなたの名前は〇〇。聞かれたら名乗り、呼ばれたら自分のことだと分かる」、`name` があるとき）+ 選んだペルソナの `prompt` + 共通の話し方の決まり（`personas.toml` のトップレベル `style_rules`。2〜4 文・箇条書きなし等）」で、通常応答・自発発話・ドラマの一言のすべてに使う。`style_rules` も保存すれば次の応答から再読み込みし、省略・空なら付けない。記憶・名前の抜き出しには使わない。
- 画面の「ペルソナ」で `ui.persona` を送り、次の応答から切り替わる（一覧に無い id は 5006）。履歴は残すので、前のペルソナの口調を真似ないよう共通の決まりに「口調は人物設定に従い、これまでの会話に合わせない」を入れる。
- 記憶（§3.4 `memories`）はペルソナごとに分ける。抜き出しを始めた時点のペルソナの id を `persona` に入れ、応答には今のペルソナの記憶と共通（NULL、v2 以前の記憶）の記憶だけを添える。保存上限もペルソナごと。会話の履歴と話者（§6.4）は共通。
- `personas.toml` は更新時刻が変わったら読み直す（不正なら warn して前の内容を使う）。選択肢の増減は `/config.json` に載るので再起動後に反映。

### 6.7 画面モード
- 画面の「画面を一緒に見る」で `getDisplayMedia`（映像のみ）により画面を共有し、`ui.screen=true` を送る。LLM が画像を読めないとき（`/config.json` の `vision` が偽）は共有を止めてエラーを出す。ドラマモードとは同時に使わない（画面で片方を無効にする。Director はドラマモードを優先）。
- 一言：IDLE で、前に画面を見に行ってから `[screen].interval_s`（既定 60 秒）経ったら、§6.5 と同じ `snap` で 1 枚求める。ブラウザは JPEG に加えて 32×18 の明るさの縮小画像 `thumb` を返す。
- 変化の判定：前に LLM に見せた画面の `thumb` との平均差（0〜100 %）が `[screen].min_diff`（既定 3）未満なら LLM を呼ばずに黙る（events に `screen_skip`、ログに差を出して調整に使う）。比べる相手は「前に LLM に見せた画面」なので、少しずつのスクロールも溜まれば話す。初回・`thumb` なしは変わったとみなす。画像が取れなければ黙る。
- 変わっていれば、ペルソナの system と画像つきの user（`SCREEN_PROMPT`：40 字以内、1〜2 文、説明・読み上げはしない、分からなければ「なし」）だけで LLM を呼ぶ（会話履歴は渡さない。§6.5 と同じ理由）。1 行目を自発発話と同じ経路（pending・保留・取消・再生完了）で読む。「なし」なら黙るが、その画面は見せたものとして次の比較の相手にする。
- 画面モード中は普段の自発発話と `IDLE_TIMEOUT` 休止を止める。共有停止で作りかけ・再生中の一言を取消す。
- 前面のウィンドウ（`[screen].follow_window`、既定オフ、Windows のみ）：ブラウザで共有せず、Director が一言の直前に前面のウィンドウを撮る（`wincap.WindowCapture`。ctypes の `GetForegroundWindow` と画面 DC からの `StretchBlt` で `[screen].width`（既定 1280）×16:9 の枠に縮め、各色を `color_bits`（既定 5）ビットに減らしてから標準の zlib で PNG にする。DPI は per-monitor v2）。1280×720 は約 370〜410 トークンで llama-server の 1 枚の上限（`n_ubatch` 既定 512）に収まるので `width` の上限は 1280。llama-server は WebP を読めず（stb_image）、JPEG は標準ライブラリで作れないため PNG にし、文字を保ったまま小さくする手段として色数を減らす（実測 2026-10-16：1280×720 で 128KB → 5 ビット 66KB、処理 35ms で変わらず。左の一覧の小さい文字を 8 ビットと同じく読めた。行フィルタ Sub/Up はかえって 15〜20% 大きくなった）。ウィンドウのタイトル（100 字まで）も LLM に渡し、タイトルが替われば画面の差に関係なく変わったとみなす。共有画面での確認が無く何でも撮るため既定はオフにし、タイトルが空（デスクトップ）・idle-talk 自身（タイトルが `idle-talk` で始まる。VS Code 等はフォルダ名を含むので部分一致にしない）・`exclude` の語を含むウィンドウと最小化中は撮らない（ログにもタイトルを残さない）。画面の DC から切り抜くので、DRM 付きの動画などは黒く写る。ブラウザの画面ボタンは共有せずオン・オフだけを送る（`/config.json` の `follow_window`）。
- 限界：ブラウザの共有は 640×360 の 1 コマなので小さい文字は読めない（前面のウィンドウは 1280×720 で読める）。差は明るさの平均なので、配色の似たページ間の移動は小さく出る。通常応答には画面を添えない（G1 に足さない）。

### 6.8 ブラウザ補正なしモード（旧称：PC と話すモード）
- 詳細は `docs/plans/2026-10-18-partner-mode.md`。
- 画面の「ブラウザ補正なし」で `ui.pc=true` を送る。共有はしない。相手（PC で動く別の音声 AI）の声は、利用者の声と同じくマイクで聞く。
- AI の声は、ブラウザではなく Director がスピーカーに鳴らす（`monitor.Monitor`、`sounddevice`、出力機器は `[pc].monitor`）。ブラウザで動く ChatGPT のエコー除去は、Chrome の別のタブが鳴らした声も消した。Chrome の外から鳴らした声は消さなかった（実測 2026-10-18）。再生の報告はブラウザと同じ形で返し、履歴の確定は今と同じ経路を通る。
- マイクも Director が録る（`monitor.MicCapture`、`sounddevice`、入力機器は `[pc].mic`）。モード中はブラウザの上りのマイクを捨てる。ブラウザのマイクは Chrome のエコー除去を通り、Chrome が鳴らした音を消すため、ブラウザの ChatGPT の声がほぼ消えて聞き取れなかった（実機 2026-10-19）。Python で録る音はエコー除去も雑音抑制も通らない。静かな部屋では RMS 0.5 程度になり、E6（無音 3 秒でマイク喪失）を誤って起こしたので、モード中の E6 は無音ではなく読み取りの失敗で判定する。
- マイクの認識結果は `turns` に role `pc`、talk.log に `PC:` で残す。LLM には今までどおり user として渡す。
- モード中は、普段の自発発話・`IDLE_TIMEOUT` 休止・相槌・名前の質問・記憶の抽出を止める。切り替えるときは、鳴っている途中の声を取り消す（前の出口の再生の報告が来ないため）。
- モード中は `duck` をモニターに渡さない（音量を下げない）。モニターの声はマイクで拾われて毎回発話開始になり、そのたびに音量が下がった（実機 2026-10-19）。割り込みは認識結果で判定する。
- モード中、AI の声の最中に始まった発話は `STOP_WORDS` を含むときだけ割り込みにし、それ以外は捨てる（events に `pc_echo_suppressed`）。マイクが拾った AI の声は「嬉しいわ」→「うれしい」、「そんなこと言われたら」→「そうね」のように聞き違えられ、文字の一致（§5.1 の自声除外）で捨てられずに中断が続いた（実機 2026-10-19。「うれしい」の声の類似度は相手の声に対して 0.18 で、AI 自身の声だった）。
- 限界：スピーカーでしか使えない。AI の声の最中の利用者・相手の発言は、停止語以外は聞き捨てる（相手が AI にかぶせて話した内容も残らない）。止まるのは認識結果が出てからになる。利用者と相手の声は区別しない。

### 6.9 カメラモード
- 画面の「カメラで見てもらう」で `getUserMedia`（映像のみ、640×360 を希望）により Web カメラを開き、`ui.camera=true` を送る。LLM が画像を読めないとき（`/config.json` の `vision` が偽）はカメラを開かずにエラーを出す。ドラマモード・画面モードとは同時に使わない（画面で他のボタンを無効にする）。
- Director は画面モード（§6.7）と同じ経路を使う（`screen_on` と `camera_on` が立つ）。`interval_s` ごとに `snap` で 1 コマ求め、`thumb` の差が `min_diff` 以上のときだけ、`CAMERA_PROMPT`（40 字以内、1〜2 文、映像の説明・容姿の評価はしない、誰も映っていない・暗いときは「なし」）と画像で LLM を呼ぶ。`[screen].follow_window` がオンでも、カメラモード中は前面のウィンドウを撮らずブラウザのカメラの画像を使う。
- 画面モードとカメラモードを切り替えたら、比べる相手の画面を捨てて見直す。
- 複数のソース（2026-10-27）：設定ファイルと同じフォルダの `cameras.toml`（パスワードを含むので git に入れない。書き方は `cameras.example.toml`）に `[[source]]` を並べる。各ソースは `label`（LLM に「このカメラ: 駐車場」と伝える名前、40 字まで）と、`url`（`"browser"` ならブラウザの Web カメラ、それ以外は ffmpeg が読める URL。rtsp は TCP）か `device`（DirectShow の機器名。idle-talk が直接撮る）のどちらか 1 つ。`interval_s` ごとに上から 1 つずつ順に見て、変化の判定はソースごとに前に LLM に見せたそのソースの画像と比べる。ブラウザ以外は `camera.grab` が ffmpeg で 1 コマを 640×360 の JPEG にし、その JPEG から 32×18 の明るさの縮小画像を作る（RTSP は 1 回 3〜4 秒、上限 15 秒。取れなければ黙る）。ファイルが無ければブラウザの Web カメラだけ。`url = "browser"` のソースが無ければブラウザは Web カメラを開かない（`/config.json` の `camera_browser`）。URL のパスワードはログに出さない（`camera.mask_url`）。
- 限界：カメラの自動露出・ノイズで `thumb` の差が出やすく、`min_diff` は画面モードと共通。映像は外部に送らず、保存もしない（`keep_snaps` は共通）。

### 6.10 文字起こしモード
- 画面の「文字起こし」で `ui.transcribe=true` を送る。共有はしない。ドラマ・画面・カメラ・ブラウザ補正なしモードとは同時に使わない（画面で他のボタンを無効にする）。オンにしたら鳴っている途中の声・作りかけの自発発話を取消す。
- マイク：ブラウザはモード中だけマイクをエコー除去・雑音抑制なし（`micConstraints(raw)`）で開き直す。Chrome のエコー除去は Chrome が鳴らした音をすべて参照にするので、別のタブで再生した動画の声をスピーカー越しに拾っても消してしまう。AI は話さないので自声の回り込みは無い。生の音は静かな部屋で無音判定（E6）を誤って起こすので（§6.8）、モード中は E6 の無音判定を切る。
- 発話検出（2026-10-28）：モード中は音量の VAD を Silero VAD（`silero_vad.SileroVad`、`data/models/silero_vad_v6.onnx`。faster-whisper 同梱のものを複製、MIT）に差し替える（`Ingress.set_vad`。モードを切ると元に戻す）。声らしさ 0.5 以上で開始、0.35 未満が 300ms 続いたら終わり。音量の VAD は BGM と声を区別できず、文の途中で切ったり何文もつなげたりした。テレビの 80 クリップを BGM つきで途切れなくつないだ音（`tools/stream_bench.py`）で CER 18.4% → 13.6%（BGM なし 25.7% → 12.8%、正しい区切りなら約 10.6%）。モデルが無ければ音量の VAD で、下の floor_track・`vad_ratio` を使う。話者の窓の「声のフレーム」も声らしさで決める。確定のしかたを「前回と今回の仮の文字で頭が揃った所から確定する」方式（前 3 秒の音を文脈に残す）に変える案は、Silero の区切りでは差が ±0.3 ポイントだったので採らなかった。
- 区間の切り方（2026-10-28 改訂）：テレビ・ドラマの音は途切れず、発話の終わりがほぼ来ない（実機 2026-10-27）。モード中は溜めた音が `TRANSCRIBE_SPLIT_MS`（8 秒）に達したら、直近 2 秒（`ingress.SPLIT_LOOK_MS`）で一番静かなフレーム（台詞の切れ目・息継ぎ）の後で切って確定し、残りは次の区間の頭にする（`Ingress._split`）。以前は `[drama].max_seg_s`（15 秒）ちょうどで切っており、語の途中で切れて前後が欠けた。
- 話者の替わり目で切る（2026-10-28）：何人もの声が混ざった 8 秒の区間は、仮の文字（区間の頭）は読めていたのに確定（区間全体）では「最高っすね」だけになった（実機）。SPEAKER 行を出したら、溜めている区間をその時刻の前後 0.5 秒で一番静かな所で切る（`Ingress.split_at`。前後が 1 秒未満なら切らない）。灰色で見えていた文字が確定で消えないよう、確定の文字を同じ区間の最後の仮の文字と合わせる（`merge_final`）。区間に「質問 → 短い返事」等の交代があると、ReazonSpeech は区間全体では前の部分を落とした（仮「じゃ一瞬しか見れないってことですか」→ 確定「そうよ」、仮「一年に一回しか咲かないからね」→ 確定「一回しか」）。確定が仮の 9 割（`PARTIAL_KEEP_RATIO`）以上の長さなら確定、短くてその 6 割（`PARTIAL_COVER`）以上が仮に順に含まれれば仮、含まれなければ仮の後ろの言葉とみなして「仮 確定」とする（idle_talk.log に `final shorter than partial`）。確定が認識の失敗・幻聴・語なしで捨てられたときも仮の文字を確定にする（`Ingress.on_discard`、`final discarded, partial kept`。補ったら捨てた区間を次の区間の頭に足さない）。以前は確定が捨てられると確定の行が出ないまま、次の確定で灰色の行だけが消えた。
- 取りこぼし（2026-10-28）：話者が替わる所で「私は」「さあ」「もう」が文脈の無い短い結果（§5.1）として捨てられ、その間の小さい声の台詞は閾値に届かず欠けた。モード中は短い結果を捨てず、閾値の倍率を `[transcribe].vad_ratio`（既定 2.0。会話は `[vad].ratio` 3.0）に下げる。5 秒ごとに閾値・雑音の推定・音量の最大・閾値を超えた割合を idle_talk.log に `transcribe level` で出す（調整用）。
- 仮の文字：溜めている間も `PARTIAL_MS`（1 秒）ごとに、そこまでの音（前の音を含む）を ReazonSpeech で認識し直し、`{"t":"partial","seg":u32,"text":str}` で画面に出す（灰色の破線の 1 行。§12.1 のスキーマ外）。`seg` はその区間を確定したときの utterance_id で、確定の `transcript` にも `uid` を付け、画面は `uid` 以下の仮の文字を消す。前の分の認識が終わっていなければ飛ばす。仮の文字は talk.log・`turns` に残さない。
- 閾値の自動校正：モード中は雑音の推定（§5.1 の自動校正）を、直近 10 秒の音量の下位 5% より上げない（`EnergyVad.floor_track`）。台詞の切れ目・音節の間の小さい音（BGM）が上限になるので、閾値は台詞の大きさまで上がらず、切れ目で区間が終わる。推定そのものを直近 5 秒の下位 10% にすると、台詞の詰まった場面で床が台詞の大きさになり、最初の一言の後は大きな音まで拾わなかった（実機 2026-10-28）。従来の推定（うるさい方へ毎秒 0.5dB）は台詞が続くと台詞の大きさまで上がり、1 分半ほど何も拾わなかった。発話中に推定を止めると、BGM の上の切れ目で区間が終わらず、すべて 15 秒で切られて 1 区間に何人もの声が混ざり、話者がまとまりすぎた（いずれも実機 2026-10-28）。
- 認識結果は自声・語なし・文脈の無い短い結果（§5.1）を除いたあと、LLM に渡さず、`_on_transcript` が False を返して待機に戻る（応答・相槌・自発発話・名前の質問・記憶の抽出・`IDLE_TIMEOUT` 休止をしない）。
- 1 発話ごとに `transcript`（話者・本文・時刻）を画面に送り、talk.log に `TEXT(始まり-終わり): 本文`（区間の時刻。話者は書かない）、`turns` に role `transcript`・本文 `話者: 本文` で残す。`turns` の `transcript` 行は会話の履歴（`history_window`）に入れない。
- 話者：§6.4 の話者識別（`[voice_id].on` が必要）で見分ける。照合の閾値は `[transcribe].threshold`（既定 0.45。会話の `[voice_id].threshold` 0.6 とは別）。スピーカー越しの動画の声は BGM も混ざり、同じ人でも類似度が 0.4〜0.5 に下がって、0.6 では 17 分で 12 人に分かれた（実機 2026-10-27）。知らない声は会話と同じく `ENROLL_N`（2）回続けて一致したら登録し、それまでは「不明」とする（1 回で登録すると外れるたびに別人が増えた）。声の特徴は発話の頭から `[transcribe].voice_max_s`（既定 8 秒）までで測る（15 秒で切った区間は複数人の声が混ざる。認識は区間全体）。1.5 秒未満の発話は声の特徴を測らず直前の話者を引き継ぐ。話者識別なしのときも「不明」。
- 話者の切り替わり（2026-10-28）：認識の区間とは別に、マイクの音を 1.5 秒の窓で 0.5 秒ずつずらして声の特徴を計算し（`speaker_track.SpeakerTrack`、別スレッド。1 窓約 39ms。計算が前の窓に追いつかなければ飛ばす）、閾値の 5 割以上のフレームが声の窓だけを `[transcribe].threshold` で照合する。窓では照合だけで登録はしない（窓で登録すると BGM 混じりの窓から仮名が 59 まで増えた。2026-10-28）。登録は確定した区間の声で行う。別の話者が 2 窓続いたら替わったとみなし、talk.log に `SPEAKER(時刻): 前の話者 → 新しい話者` を出す（時刻は替わった最初の窓の真ん中）。時刻は TEXT 行と同じくマイクの音のフレーム番号から出すので、後で突き合わせられる（行の順は出来上がった順）。区間が長く何人もの声が混ざっても、どこで替わったかが残る。1.5 秒より短い発言での切り替わりは捉えない。画面のラベルは今までどおり区間の声で決める。
- 仮名：名前（§6.4）があれば名前、無ければ `speakers.alias`。仮名が無い声は、初めて文字起こしで聞いた発話の音から「言葉 + 通し番号」で付けて保存する（以後のセッションでも同じ）。言葉は声の高さ（有声フレームの F0 の中央値。自己相関で 70〜500Hz を探す）が 125Hz 未満「低い」、165Hz 未満「やや低い」、220Hz 未満「やや高い」、それ以上「高い」と、抑揚（F0 の標準偏差、半音）が 2.0 未満「落ち着いた」、3.5 以上「抑揚のある」を組み合わせる（例：「低く落ち着いた声」「やや高い声」「高く抑揚のある声」。区切りは暫定）。有声部分が 0.2 秒未満なら「声」。番号はこれまでに付けた仮名の最大 + 1（言葉によらず通し）。ctl の `speakers` に仮名も出る。
- 限界：仮名の言葉は最初の 1 発話で決まり、その発話の調子に左右される。声の似た人は同じ話者になり、同時に話すとどちらか 1 人になる。

## 7. エッジケースと障害モード

E1〜E15 の検知・対処・テストは §12.3 に一本化する。

セキュリティ/プライバシー：音声と書き起こしは外部送信しない。ニュース取得（M4。`[search].on` なら話題カードの補充に Bing ニュース検索も使う。`[topics].x_trends` なら X のトレンドも取る）と Web 検索（§6.3、`[search].on` のときのみ。送るのは LLM が作った検索語と読むページの URL だけ。`[search].realtime` なら同じ検索語を Yahoo! リアルタイム検索にも送る。`[search].read_window` なら、見ているページを頼まれたときだけその URL を r.jina.ai に送る。要約を頼まれたら、その URL を含む ChatGPT のページをブラウザで開く）以外のネットワークアクセスなし。ドラマモード（§6.5）の音声・台詞・画面は外部に送らず、保存もしない（台詞はメモリの直近 `window_s` 秒のみ、画面は一言・感想に使う 1 枚だけで使ったら捨てる。画面はローカルの llama-server にだけ渡す）。ただし `[drama].log_prompt`（既定オフ）がオンのときは、一言・感想・要約で LLM に渡した台詞とあらすじメモを `data/talk.log` に `DRAMA(...)` 行で残す（画像は大きさだけ）。`[drama].keep_snaps`（既定 0）が 1 以上なら、一言・感想に使った画面を `data/snaps/snap-<日時>-<id>.jpg` に新しい方からその枚数だけ残す（古いものは消す）。PC と話すモード（§6.8）の相手の発話は、利用者の発話と同じく `turns` に保存する（外部には送らない）。画面モード（§6.7）・カメラモード（§6.9）の画面も同じ扱い（`cameras.toml` のネットワークカメラは、LAN 内のその URL に ffmpeg で接続する）（ローカルの llama-server にだけ渡し、縮小画像は比較用にメモリに 1 枚だけ置く。`keep_snaps` は共通）。保存データは SQLite のみで利用者が全削除できる。声の特徴（§6.4）も SQLite にだけ保存し、外部に送らない（ctl の `speakers` で確認・削除）。localhost バインドと Origin 検証で他サイトからのアクセスを遮断する。

## 8. 遅延予算と性能設計

応答遅延を終話待ち → ASR 確定 → LLM の最初の合成可能な節 → TTS 合成 → 再生開始に分解して記録する。目標値は §1.2 の G1、ここでは配分のみ。

|段階|p50 配分 (ms)|備考|
|---|---|---|
| 終話待ち（固定無音 `T_silence`） | `T_silence` 値（§8.1） | 既定値は §8.1 |
|ASR 確定|200|GPU0 想定|
|LLM 最初の合成可能な節|300|4B/9B で M0 比較|
|TTS 最初の文|250|閾値は `TTS_GPU_THRESH`（§8.1）|
|合計|`T_silence` + `VAR_SUM`|G1 p50 との差が余裕|

検算。
- G1 p50：合計 = `T_silence` + (ASR + LLM + TTS の配分) ≤ G1 p50 で合格。既定の余裕 = G1 p50 − (`T_silence` + `VAR_SUM`) = 1200 − 1150 = 50ms。合計 1200 は合格、1201 は不合格。
- G1 p95：固定の `T_silence` には倍率をかけず、可変段 `VAR_SUM` にのみ倍率 k を適用する。`T_silence` + `VAR_SUM`·k ≤ G1 p95 より k ≤ (G1 p95 − `T_silence`)/`VAR_SUM` = 2.1333…。実測 p95/p50 の各段比 r を k として代入し、r ≤ k なら合格（k=1.7 は合格、k=2.14 は不合格）。
- G2（VAD 経路）：VAD 判定窓 1 フレーム（最大 40ms、§3.1）+ Director の `duck`/`cancel` 送出（60ms 予算）+ ブラウザの音量変更・破棄（30ms 予算）= `G2_SUM` ≤ G2（既定 130 ≤ 250）。
- 停止語・継続発話経路：確定 `cancel` までは `T_confirm` + `G2_SUM`（範囲の下端 300 で 430ms、既定 400 で 530ms、上端 500 で 630ms）。この経路は G2 の対象外（G2 でダッキングは始まる）。STRONG_UTT の継続条件は窓終端で評価するため同経路。
- G4：許容件数ちょうどは合格、+1 件で不合格。G3：旧音声 1 件でも不合格。G5：傾き 1MiB/h なら 8 時間で +8MiB（ちょうどは合格）、+9MiB は不合格。
- STRONG_UTT：直近 1s 平均音量 0.1 に対し 0.2 は成立、0.19 は不成立。
- N_TURNS：8 ターン x 250 トークン + システム 500 = 2500 ≤ ctx 4096。
- TTS 比（`TTS_RATIO_MAX`=0.7、判定は「<」）：3.0s の音声を 2.0s で合成すれば 0.67 で合格、2.1s なら 0.70 で不合格。

計算量：VAD/ASR は発話長 n に対し O(n)。履歴は `N_TURNS` で制限し LLM 入力は O(1)。Qwen3.5 でキャッシュ再利用が効かなければ Qwen2.5-7B や Gemma 系を予備として比較する。事前合成の相槌音は遅延計測に含めない。

## 9. 実測による既定値更新ルール（M0）

- LLM：既定 4B。9B は、遅延目標（§1.2 G1）を満たし、30〜50 場面のブラインド比較で品質が明確に勝つ場合のみ昇格。判断材料は 9B の VRAM、最初の1文までの時間、20 ターンのキャッシュ効果。
- ASR 配置：既定 GPU0。GPU1 負荷変動、同居時の LLM 遅延、割り込み時の重なり遅延（`OVERLAP_MAX`）で判断。
- TTS 配置：既定 CPU。最初の1文の合成が `TTS_GPU_THRESH` を超えたら GPU1 DirectML と比較。
- 終話判定：既定は固定無音。G4 の試行での早切り数で Smart Turn v3.2 と比較。
- 上限は §1.4。思考無効はテンプレート設定で行い、実出力に思考が出ないことを確認する。

- llama-server req：`{"type":"object","required":["model","messages","stream","max_tokens"],"additionalProperties":false,"properties":{"model":{"const":"local"},"messages":{"type":"array","items":{"type":"object","required":["role","content"],"properties":{"role":{"enum":["system","user","assistant"]},"content":{"anyOf":[{"type":"string"},{"type":"array","minItems":1,"items":{"oneOf":[{"type":"object","required":["type","text"],"properties":{"type":{"const":"text"},"text":{"type":"string"}}},{"type":"object","required":["type","image_url"],"properties":{"type":{"const":"image_url"},"image_url":{"type":"object","required":["url"],"properties":{"url":{"type":"string","pattern":"^data:image/"}}}}}]}}]}}}},"stream":{"const":true},"max_tokens":{"const":120}}}`。res は SSE 各 data 行：`{"type":"object","required":["choices"],"properties":{"choices":{"type":"array","items":{"type":"object","required":["delta"],"properties":{"delta":{"type":"object","properties":{"content":{"type":["string","null"]}}}}}}}}`、終端は `[DONE]`。エラー：`err` または `HTTP_TIMEOUT` 超過→定型句 + `LLM_RETRY`。
- AivisSpeech：`POST /audio_query?text=..&speaker=<id>` → JSON(AudioQuery)、続けて `POST /synthesis?speaker=<id>`（body=AudioQuery）→ WAV。`/synthesis` はキャンセル不可のため、中止は epoch 不一致での破棄で代替する（`/cancellable_synthesis` は AivisSpeech Engine 1.2.0 で 501）。エラー：`err` または `HTTP_TIMEOUT` 超過→該当文を飛ばす。
- ASR ワーカー req：`{"type":"object","required":["utterance_id","pcm_ref","lang"],"additionalProperties":false,"properties":{"utterance_id":{"type":"integer","minimum":0,"maximum":4294967295},"pcm_ref":{"type":"string","minLength":1},"lang":{"const":"ja"}}}`（pcm_ref は共有メモリ名）。res：`{"type":"object","required":["utterance_id","text","no_speech_prob","compression_ratio"],"additionalProperties":false,"properties":{"utterance_id":{"type":"integer","minimum":0},"text":{"type":"string"},"no_speech_prob":{"type":"number","minimum":0,"maximum":1},"compression_ratio":{"type":"number","minimum":0}}}`。エラー：不正 req→HTTP 400 + `err`、`HTTP_TIMEOUT` 超過→発話を破棄しログ。


設定名の一覧：本書で `T_silence` のように示す全変数は §8.1 が唯一の定義で、その表が Options 型（名前・型・既定値）を兼ねる。メッセージ別のエラー条件：`playback` の epoch が現在値と異なる→破棄 + log、`ui` の値が範囲外→5006 を返し既存設定を維持、サイズ超過のバイナリ→破棄 + log。

### 12.2 エラーコード（4xxx は WS close code、5xxx はアプリ内 error メッセージ。二重起動はプロセス終了コード 4）
|code|意味|対処|
|---|---|---|
|4001|4002|version 不一致|UI に更新を促す|
|4003|Origin 不許可|接続拒否|
|5001|LLM タイムアウト/停止|定型句 + 再起動|
|5002|TTS 失敗/タイムアウト|文を飛ばす|
|5003|ASR 失敗|発話破棄|
|5004|DB 異常|`DB_BACKUP` から復元|
|5006|ui/playback の範囲外値|設定維持|
|5005|マイクデバイス喪失（E6）|休止|

### 12.3 障害モードの対応表（E-ID → 機構 → テスト）
|E-ID|機構|テスト（合否）|
|---|---|---|
|E1|終話確認中の VAD 再開で取消|T-E1：「今日は〜けど、」+ `T_silence` 未満の無音 + 続き。応答 0。無音が `T_silence` ちょうどで終話確認成立（境界）|
| E2 | ダッキング + `T_confirm` 判定 + resume | T-E2：再生中に「うん」`TEST_N`。`cancel` 0 件かつ再生位置が `T_confirm` 後に進行 |
| E3 | `STOP_WORDS` で即 cancel | T-E3：「待って」`TEST_N`。ダッキング開始が G2 以内、確定停止が `T_confirm` + `G2_SUM` 以内 |
| E4 | `ASR_HALLU` フィルタ | T-E4：無音 `E_PARAMS` の入力で出力 0 件 |
| E5 | `PING_INTERVAL` + epoch+1 | T-E5：WS 強制切断。`PING_INTERVAL` x 2 以内に検知、再接続後の旧音声 0 |
| E6 | 無音フレーム連続（`E_PARAMS`）で休止 | T-E6：デバイス抜去から `E_PARAMS` の休止条件 + 2 秒以内に `休止` 表示 + 5005 |
| E7 | `LLM_RETRY` + 定型句 | T-E7：llama-server プロセスを kill。`HTTP_TIMEOUT` 内に定型句、`LLM_RETRY` の初回バックオフ内に再起動し次ターンで応答 |
|E8|1 文単位の合成 + 直列化 + epoch 破棄|T-E8：合成中に切断し、`HTTP_TIMEOUT.tts_sentence` + `E_PARAMS` 内に TTS CPU が待機水準へ|
|E9|ASR/LLM を GPU0 固定|T-E9：GPU1 で GPU 使用率 90% の負荷（`TEST_N`）をかけ、G1 を満たす|
|E10|ブラウザ AEC + 自声除外（§5.1。認識結果が直近 AI 本文に含まれれば破棄）|T-E10：再生中に AI 本文と同じ認識結果。応答・`cancel` 0、`resume`、`echo_suppressed` 1 件。M5：再生中の自己認識による応答連鎖 0 回 / 20 分|
|E11|M0 で重なり遅延を測定|T-E11：割り込み重なりを `TEST_N` 再現し、追加遅延 p95 が `OVERLAP_MAX` 以内。超過で ASR を GPU1 へ|
|E12|`N_TURNS` 切り詰め|T-E12：G5 の試験で RSS 回帰傾きが G5 の値以内|
| E13 | E14 | 起動時 `integrity_check` + `DB_BACKUP`（§8.1） | T-E14：DB の先頭 100 バイトを破壊して起動。復元後の `turns` 行数が破壊前と一致 |
| BC | `SIL_BACKCHANNEL` 取消規則 | T-BC：無音が `T_silence` に達した試行で相槌 0 件、未達の試行で 1 件以下 |
|E15|epoch 比較で破棄|T-E15：発話 A の ASR と LLM に各 1500ms の遅延を注入し、A の 500ms 後に発話 B（epoch+1）を入力する試行を `TEST_N` 回。合格＝旧 epoch の再生 0/`TEST_N` かつ破棄 log 件数＝`TEST_N`|

防御しないもの：スピーカー時のエコー連鎖（M5 まで）、ASR の誤認識自体、GPU1 他アプリによる VRAM 枯渇。

### 12.4 防御機構ごとのトレードオフ
|機構|想定する誤検知|代替案|判断（reject/warn/log）|
|---|---|---|---|
|Origin 検証|Origin を付けない拡張|トークン認証|reject（4003）+ log|
|停止語辞書|「ちょっと」で誤停止|長さのみで判定|即停止 + log|
|幻聴フィルタ|小声の正規発話を破棄|除外リストのみ|破棄 + warn|
|ダッキング|停止遅れ|常に即停止|判断不能は停止|
|接続置換|二重タブで切断|後着を拒否|最新優先 + log|
|ping/pong|一時遅延で切断扱い|無期限待ち|欠落 2 回で切断 + log|
|ポートロック|ロック残り|PID ファイル|起動時に生存確認、reject|
|LLM 再起動上限|一時障害後に復帰しない|無制限再試行|超過で休止 + warn|
|`MIN_SEG`|短い正規発話（「うん」）を雑音扱い|閾値なし|破棄 + log|
|`T_confirm`/`STRONG_UTT`|長い相槌を割り込みと誤認|窓なし即停止|停止 + log|
|`SIL_BACKCHANNEL` 取消|相槌が出ず間が悪い|取消なし|取消 + log（T-BC）|
|epoch 破棄|正規の遅い結果も捨てる|全結果を再生|破棄 + log|
|履歴切り詰め|古い文脈の喪失|要約|切り詰め + log|
|localhost バインド|別 PC から使えない|認証付き公開|127.0.0.1 のみ（§6.2 の移行条件を満たすまで）|
