# 質問で終わり続ける発話への対策案

作成日: 2026-10-19。初回調査後の利用者の指摘を反映し、質問を自然に残す方針へ修正。共通指示・通常自発発話・ドラマの総合感想の指示を調整した。実機での負担軽減の検証は未実施。

## 結論

**感想・共感・連想で終える回と、相手の話を聞きたくて自然に質問する回を織り交ぜる。毎回の締めに質問を付け足す癖を減らす。**

質問や問いかけが全くない会話も不自然、という利用者の指摘を採用した。「自発発話は原則質問なし」や低い質問率を目標にする初案は採用しない。今回はプロンプトだけを調整し、固定の質問率・待ち回数・出力削除は導入しない。

自己開示・感想・共感・連想の種類を増やすだけでは足りない。すでにそれらを含む発話でも、最後に質問を付けることで、相手に次の発話の仕事を渡してしまっている。会話の内容と「返答を求めるか」を別々に決める必要がある。

## 対策1: 質問する回と感想で終える回を混ぜる（今回実施）

最初に行う変更。まずは生成回数や待ち時間を増やさずに試せる。

共通指示の候補:

> 質問する回と、感想・共感・連想で終える回を自然に織り交ぜてください。相手の話をもっと聞きたいときは質問して構いませんが、毎回の締めに質問や『教えて』『聞かせて』を付け足さず、質問が続いたら自分の話や感想で返してください。

通常の自発発話の候補:

> 利用者は黙っています。{topic}について、自分の感想を添えて短く話してください。感想で終える回と、話の流れで気になることを自然に一つ尋ねる回を織り交ぜてください。

「最後に軽く質問」を両方の通常自発発話経路から除き、共通指示にも自然に混ぜる方針を置いた。ラジオ・ドラマの一言は既存の返答不要方針を維持し、ドラマの総合感想も毎回質問を要求する指示から変更した。

質問を禁止するだけだと「詳しく聞かせて」に置き換わりうるため、返答要求を対象にする。「返事はいらないよ」を毎回付けるのも定型化するので、基本は何も添えず内容で終える。

## 対策2: 偏りが残る場合の追加検討（今回は未実施）

2026-10-27 追記: カメラモードの実機で、対策1 の後も通常応答がほぼ毎回質問で終わった。直近 2 回の再生済み AI 発話に質問終わりがあれば、次の生成に「今回は質問で終えない」指示を足す制御 (`RATIO_Q`、`director.NO_QUESTION_NOTE`) を入れた。出力の削除はしない。

指示変更だけで偏りが残る場合の次の段階。モデル任せの「ときどき」を、生成前の短い方針指定に置き換える。

- 感想・共感・連想と質問の偏りを履歴から見て、生成前に短い方針を添える方法を検討する。質問を原則禁止する既定値は設けない。
- 固定の質問率や待ち回数は会話を機械的にする可能性があるため、今回採用しない。
- 前の質問が未回答のまま沈黙・話題変更になったら、回答を催促せず別の感想や話題に進める。未回答状態を扱う場合も、意味的な回答判定を正規表現だけで実装しない。
- 相手が「質問して」「聞いてほしい」と望んでいる場合や、依頼の実行に不可欠な確認は例外。回数枠を消化するために質問しない。
- 「疲れた」「眠い」など明示的な発話があれば、さらに返答を求めない。短い返答だけから心理状態を決めつけない。
- 間隔の状態は実際に再生された発話に基づける。生成後に破棄された発話や、割り込みで質問まで再生されなかった発話を「質問済み」として扱わない。

感想・共感・自己開示・連想を固定順に回す必要はない。同じ「感想」の発話でも、質問を付けるかどうかは別の判断にする。

名前を尋ねる専用経路（`director.py:666` の `_speaker_section`）もあるので、必要な確認まで一律に潰さず、任意の雑談質問とは区別する。

## 発話の変化の例

以下は提案文であり、モデルの生成結果ではない。

| 場面 | 望ましい終え方の例 |
| --- | --- |
| 「動くんか」への返答 | 「動いとるばい。声が届いて、うちもちょっと嬉しかね。」 |
| 食べ物を連想したとき | 「こんな時間は、あったかいスープの話だけでお腹すいてくるね。」 |
| 「とりあえず」への返答 | 「ひとまず一歩、やね。そのくらいの始め方も悪くなかよ。」 |
| ニュースの自発紹介 | 「この仕組み、身近な道具に入ってきたら面白そう。派手さより、毎日の小さな面倒が減る感じが好きやね。」 |

どれも相手は続けても黙っていてもよい。毎回「休んでね」「おやすみ」で会話を閉じたり、発話を一律に短くすることを目的にしない。

## 出力後の機械的な削除は第一案にしない

「最後の疑問文を削る」「？を消す」は、必要な確認を失い、文のつながりを壊しうる。さらにこの実装は節単位でTTSへ送る（`pipeline.py:51` の `play_utterance`）ため、全文を待って書き直す方式は遅延と再生成コストを増やす。

まず生成前の指示で改善し、違反が多い場合にだけ追加の検出・制御を検討する。

## 改善の確認方法

1. 通常応答、ニュースあり・なしの自発発話、ラジオ、ドラマの一言・総合感想を別々に評価する。現在のログでは分離しきれないため、今後は生成経路・モード・質問方針を会話本文とは別のイベントに残す。
2. 各経路で同じ入力・モデル・設定・履歴を用いて変更前後を比較する。新規会話と、末尾質問の多い既存履歴を両方含め、確率的なばらつきが分かるよう複数回生成する。
3. 疑問符率に加え、返答要求の割合、質問の連続回数、無反応後の催促、話題の関連性・自然さ・発話長・再生開始までの遅延を確認する。「〜だよね」等をすべて返答要求と機械判定しない。
4. 質問する回と感想だけで終える回の両方があり、無関係な質問の付け足しや質問の連発が減るかを確認する。質問ゼロや一律の質問率を合格条件にはしない。必要な確認や質問を望まれた会話は別集計にする。
5. ログ上の質問率が下がっただけで負担軽減と断定しない。実際に聞いた際の自然さと、返さずに置いておける感覚で最終判断する。

推奨順序は **共通指示と自発発話の末尾指示を一緒に修正 → 同条件で比較 → 残る偏りにだけ頻度制御を追加**。
